# Scene Acting Studio (5Bricks)

출연진(1~4명) → 표정 → 대사 → 액팅 → 영상 프롬프트를 한 단계씩 검토·승인하며, **한 명의 인물 연기 쇼트부터 2~4명이 함께 나오는 대화 장면까지** 만드는 팀용 웹앱입니다.
[Facial Acting Studio](#facial-acting-studio에서-달라진-점)를 바탕으로 만든 별도 앱이며, 출연진이 1명이면 Facial Acting Studio와 같은 결과를 냅니다.

- **분석·설계·상의:** Claude (기본 모델 `claude-opus-5-5`)
- **그림 생성:** Higgsfield **구독 크레딧**
  - 표정 그림(표정마다 한 장: 1명이면 세로 3:4 인물 그림, 2명 이상이면 모든 인물이 들어간 장면 그림을 영상 비율로. 구도는 클로즈업·바스트 샷·미디엄 샷 중 선택 — 여러 인물은 바스트·미디엄만, 첫 표정을 연결 기준 그림으로 삼아 나머지를 같은 구도·크기·위치로 그림, Nano Banana 2.1 · 1K / GPT Image 2.5 · 1K — 영상에는 각각 참고 그림으로 첨부)와 영상(Kling 4.0 · Seedance 2.5 드래프트/720p/1080p · MiniMax H3 2K)을 앱에서 바로 생성합니다. Higgsfield 공식 MCP 서버를 통해 연결된 계정·워크스페이스의 구독 크레딧이 차감됩니다.
  - Higgsfield 종량제 API(별도 잔액)는 쓰지 않습니다.
  - 수동 방식(프롬프트·참고 그림 묶음을 higgsfield.ai에 직접 넣기)도 남아 있습니다.
- **저장·로그인·권한:** Supabase / **배포:** Vercel

## 1단계: 시나리오가 기준, 그림은 선택

1. **씬 시놉시스·시나리오**(기초 대사 포함, `이름 : “대사”`)를 씁니다. 2단계 설계와 3단계 대사가 이 글을 따릅니다(2단계의 같은 칸과 같은 글).
2. **AI로 씬 구성**: 시나리오와 인물 자료(인물 카드의 ‘이 인물 참고 자료’, 추가 참고 그림, 장면 기준 그림이 있으면 그것까지)로 주요 인물·외형·의상·그림체·군중·**첫 장면 묘사**를 제안합니다. 고른 항목만 적용됩니다.
   - **쇼트 구성**도 함께 제안합니다: 쇼트(컷 분할) 몇 개, 쇼트마다 패널 몇 개와 한 줄 설명, 쇼트별 길이와 전체 길이(시나리오의 타임코드가 있으면 그 길이). 적용하면 컷 수·컷 제목·연결(✂/→)·시간 배분이 한 번에 맞춰지고, 2단계의 ‘AI로 콘티 설계’가 그 구성을 따라 내용을 채웁니다. 인물별 연기 방식은 한 쇼트라 패널이 표정 비트가 됩니다. 스토리보드 최대 6컷(인물별 연기 8개)·60초.
3. **장면 기준 그림**을 두 가지 중 하나로 정합니다.
   - **시나리오로 첫 장면 생성**(그림이 없을 때 기본): 첫 장면 묘사·인물 자료로 Higgsfield가 첫 순간을 그리고, 고른 그림이 장면 기준 그림이 됩니다. 모든 주요 인물의 얼굴이 보이게 그리라고 지시합니다.
   - **그림 올리기**: 가진 그림을 올리고 ‘AI로 장면 기준 그림 분석’으로 설명 초안을 받습니다.
4. 장면 기준 그림이 있어야 1단계를 승인할 수 있습니다(올린 것이든 생성한 것이든).

## 여러 인물 장면 (출연진 2~4명)

한 씬의 인물들을 **하나의 그림으로 함께 통제**합니다. 새 장면을 만들 때 출연진 수(1~4명)를 고르고, 1단계에서 언제든 인물을 더하거나 뺄 수 있습니다.

| 단계 | 1명 | 2~4명 |
|---|---|---|
| 1 출연진 | 기본 그림·특징·외형·의상 | **장면 기준 그림 한 장**(출연진 전원이 함께 그려진 그림)에서 모든 인물의 모습·키 차이·그림체를 가져옴. 인물마다 이름·**화면 위치**(그림 속 위치와 같게, 쇼트 내내 고정)·특징·외형·의상. AI 분석은 그림 한 장으로 모든 인물을 한 번에 |
| 2 표정 | 세로 3:4 인물 그림 | 표정(비트)마다 **모든 인물의 연기**(감정·강도·눈썹·눈·입·팔손·방향)를 한 카드에서 함께 정함. **중심 인물**(대사가 있으면 말하는 인물)을 바꿔도 각자의 연기는 그대로. 그림은 모든 인물이 들어간 장면 그림, 영상과 같은 비율(가로 16:9 권장). 클로즈업은 막힘 |
| 3 대사 | 목소리 하나 | **인물마다 목소리**. 대사는 그 표정의 중심 인물이 말함 |
| 4 액팅 | — | 타임라인 구간에 중심 인물 이름 표시 |
| 5 영상 | — | 프롬프트에 출연진·위치, 구간마다 모든 인물의 연기, 인물별 목소리, 대사마다 말하는 인물, “듣는 인물은 입을 다묾” 지시. 참고 그림은 장면 기준 그림이 먼저, 그다음 장면 그림(합계 7장까지). 프롬프트 길이 목표는 인물 한 명당 900자씩 늘어남 |

- 인물 이름은 프롬프트에서 인물을 구분하는 열쇠라 겹치면 승인할 수 없습니다. 장면 기준 그림 속 위치와 화면 위치를 맞추세요(프롬프트가 “화면 왼쪽의 진홍색 머리 인물이 칼리엘라”처럼 그림 속 인물을 짚어 줍니다).
- 모든 인물의 감정과 확인된 방향이 있어야 2단계를 승인할 수 있습니다. AI가 제안한 방향은 인물마다 확인해야 합니다.
- 대사가 있는 인물은 목소리가 있어야 승인됩니다. 렌더 전 점검도 목소리가 빠진 인물, 참고 그림 한도로 빠진 장면 그림을 알려 줍니다.
- 상황 설정의 기초 대사에 화자를 적으면(`브람 : “…”`) AI가 그 인물을 중심 인물로 배정합니다.
- 영어 정리는 인물마다(특징·의상·목소리), 표정마다 모든 인물의 연기까지 만들어지고, 바뀐 부분만 다시 정리하라고 알려 줍니다.
- Kling 4.0이 여러 인물·대사 분리에 가장 안정적입니다.

## 스토리보드 방식 (컷 단위 통제)

장면마다 **통제 방식**을 고릅니다(새 장면 만들 때, 또는 1단계에서 언제든 바꿀 수 있고 쓴 내용은 남습니다).

| | 인물별 연기 | 스토리보드 (컷 단위) |
|---|---|---|
| 한 비트를 정하는 법 | 인물 한 명 한 명의 감정·얼굴·팔손·방향 | 컷 하나 = 그 순간 화면 전체: **장면 묘사**(누가 무엇을, 군중 포함) + **카메라** + 말하는 인물 |
| 그림 참고 | 장면 기준 그림 | 장면 기준 그림 + 컷마다 **러프 스케치(콘티 칸, 선택)** — 구도·자세·카메라만 따르고 선 그림체는 따르지 않음 |
| 인물 위치 | 쇼트 내내 고정 | 컷마다 달라도 됨 (인물은 이름·특징으로 지킴) |
| 이름 있는 인물 수 | 1~4명 | 1~8명 (5명부터는 프롬프트에 인물마다 핵심 특징 2개씩) |
| 군중 | 다루지 않음 | 1단계 ‘군중·배경 인물’에 한 번 적으면 모든 컷·영상에 같은 모습으로 |
| 컷 그림 | 1명 세로 3:4 / 여러 명 영상 비율, 흰 배경 | 항상 영상 비율, 배경과 세계까지 그린 완성 그림 |
| 승인 조건 | 모든 인물의 감정·확인된 방향 | 컷마다 장면 묘사 또는 러프 스케치 |
| 맞는 장면 | 1~4명이 연기하는 장면을 정밀하게 | 군중 장면, 장면 전환이 많은 장면, 빨리 만들어야 할 때 |

- AI 콘티 설계: 컷 수만큼 제목·장면 묘사·카메라·말하는 인물을 제안합니다. 러프 스케치를 올린 컷은 그 구도를 풀어 씁니다.
- 스토리보드 컷 수는 2~6개(인물별 연기 방식의 표정은 2~8개)입니다. 넘는 예전 장면은 2단계에서 줄이라는 안내가 나오고 승인이 막힙니다. 컷 카드의 ‘앞 컷과의 연결’에서 ✂ 컷 분할(새 쇼트)과 → 이어짐(카메라 이동)을 고르며, 쇼트 수에는 제한이 없습니다.
- 연결성: AI 콘티 설계는 먼저 **장면 연결 규칙**(180도 축과 인물의 화면 좌우, 장소 지리, 빛 방향, 의상·소품 변화와 그 시점, 동선)을 정하고, 컷마다 **연결 상태**(화면 위치·보는 방향·이동·의상/소품·빛)를 앞 컷에서 이어지게 씁니다. 둘 다 2단계에서 고칠 수 있고, 컷 그림·영상 프롬프트·AI 그림 검사에 함께 들어갑니다. 컷 그림은 바로 앞 컷의 완성 그림도 참고 그림으로 받아 의상·좌우·위치·빛을 이어 그리고, ‘연결성 우선: 앞 컷부터 한 장씩 차례로 생성’은 컷을 하나씩 만들어 자동 적용하면서 다음 컷이 앞 컷을 보고 그리게 합니다.
- 팀 가이드(애니메이션 8원칙·스토리보드 연속성) 반영:
  - 컷(표정)마다 **우선 원칙 2~3개**(스쿼시 앤 스트레치, 안티시페이션, 포즈 투 포즈, 팔로우 스루와 오버래핑, 슬로우 인·아웃, 아크, 타이밍과 스페이싱, 스테이징)를 AI가 고르고 카드에서 바꿀 수 있습니다. 영상 프롬프트에는 원칙 이름이 아니라 그 원칙이 요구하는 움직임 문장으로 들어갑니다.
  - AI 설계는 동작을 ‘시선 → 준비 → 행동 → 접촉 → 정착’ 순서의 관찰 가능한 움직임으로, 좌우는 화면 기준/몸 기준을 붙여, 카메라는 고정 또는 한 가지 이동과 시작·끝 구도로 씁니다.
  - 연결 상태는 HU(훅업) ‘시작 / 끝’으로 기록하고 다음 컷의 시작 = 앞 컷의 끝(몸 위치·시선·몸 기준 손·발 접지·소품·동작 단계·감정·빛). 동작 중 컷이면 다음 단계부터 잇고, 포즈 리셋·동작 중복·잡은 손 바뀜 등 나쁜 사례를 피합니다.
  - 2단계 ‘애니메이션 원칙·연속성 점검’과 렌더 전 점검이 카메라 이동 섞임, 모호한 표현(‘자연스럽게’ 등), 비어 있는 연결 상태를 알려 주고, AI 그림 검사·프롬프트 검사는 가이드의 검토 순서(방향·위치 → 시선 → 접촉·행동 → 형태)와 오류 목록으로 봅니다.
- 컷 그림의 연결: 바로 앞 컷의 완성 그림과 함께 앞 컷의 ‘끝 상태’ 글이 넘어가 이 컷이 거기서 시작합니다. 장면 기준 그림은 인물·세계만 참고하고 구도는 이 컷의 카메라를 따르며, 다른 쇼트(다른 장소·시간)의 그림은 상태를 끌어오지 않습니다. AI 그림 검사가 끝나면 지적된 컷을 ‘지적 내용대로 다시 생성’할 수 있고, 지적 내용은 그 컷 프롬프트에 ‘고칠 점’으로 들어갑니다.
- 움직임 무게감(5단계): ‘실제 무게 / 무겁게(기본) / 과장(중력 2배)’. 스튜디오 제약사항은 긍정형 블록([MOTION] 스톱모션 박자, [WEIGHT] 실제 속도·짧은 체공·강한 착지·고정된 발, [CAMERA] 손에 든 핸드헬드(감독이 장비를 정하면 그 장비), [SOUND] 자연음·무거운 충돌음, [SECONDARY ACTION] 무겁게 빨리 떨어지는 머리카락·옷)으로 들어가고, 피할 것은 본문에 부정문으로 쓰지 않고 네거티브 프롬프트로 따로 줍니다(영상 단계 복사 칸·ZIP의 네거티브프롬프트.txt — Higgsfield 직접 생성에는 네거티브 칸이 없어 쓰이지 않음). AI 설계는 무게를 숫자가 아니라 보이는 결과로 쓰고, 넘어짐·낙하는 0.5초 안팎으로 짧게 둡니다.
- **콘티 방식(스토리보드 기본 흐름)**: 1단계에서 인물별 캐릭터 시트와 장면 기준 그림을 정하고, 2단계에서는 러프 콘티만 패널로 만듭니다(완성 컷 그림은 선택). 3·4단계에서 대사·액팅을 확정하면, 5단계 영상은 ① 캐릭터 시트 → ② 장면 그림·배경·에셋 → ③ 러프 콘티 순서로 참고 그림을 붙이고, 프롬프트가 각 그림의 역할(시트=얼굴·머리·체형·의상 디자인, 장면 그림·배경=세계·빛·그림체, 러프 콘티=구도·동선·포즈·카메라만, 선 그림체는 따르지 않음)을 지시합니다. 5단계 ‘참고 그림 구성’에서 자동(모든 컷에 러프 콘티가 있으면 콘티 방식) / 콘티 방식 / 완성 컷 그림 방식을 고릅니다. 2단계 AI 검사도 콘티 방식이면 러프 콘티의 구도·배치·연결을 봅니다.
- 러프 콘티 바로 생성: ③ 컷 카드 위의 ‘러프 콘티 전부 생성’이 컷마다 장면 묘사·카메라대로 흰 배경에 단순한 검은 선으로만 그린 콘티를 한 번에 만들어 각 컷의 ‘러프 스케치’ 칸에 넣습니다(장면 기준 그림은 누가 누구인지·배경 배치만 참고, 품질 낮음으로 저렴하게). 컷 카드의 ‘러프 콘티 다시 생성’으로 그 컷만 다시 만들거나, 직접 그린 그림으로 바꿀 수 있습니다. 컷 그림은 이 구도를 따릅니다.
- 추가 참고 그림(배경·소품·분위기)은 5장까지 올릴 수 있습니다. 그림 생성 한 번에 붙는 참고 그림은 최대 12장이라, 인물 자료가 많으면 추가 참고 그림이 뒤에서부터 빠집니다.
- 영상 프롬프트: “스토리보드 컷들은 같은 쇼트의 연속된 순간이고, 카메라가 컷 사이를 끊지 않고 이어서 움직인다”는 지시 아래 컷마다 Action·Camera·대사를 넣습니다. 군중 소리는 말소리 없는 자연음만 허용합니다.
- **컷 분할**: 컷 카드마다 ‘앞 컷과의 연결’을 **→ 이어짐(카메라 이동)** 또는 **✂ 컷 분할(새 쇼트)** 로 고릅니다. 컷 카드 위의 쇼트 구성 줄(예: `쇼트 1: 1 ✂ 쇼트 2: 2 → 3 ✂ 쇼트 3: 4`)로 한눈에 봅니다. 전부 이어짐이면 컷 없는 한 쇼트, 컷 분할이 있으면 영상 프롬프트가 쇼트 구성을 밝히고 표시한 곳에서만 컷을 바꾸라고 지시합니다(이때 장면 묘사의 ‘컷’ 표현은 고치지 않음). AI 콘티 설계도 시나리오의 컷 나눔을 보고 연결을 제안합니다.
- 컷 그림이 영상 모델의 참고 그림 한도(장면 기준 그림 + 6장)보다 많으면, 이어지는 컷을 한 장에 왼쪽부터 나란히 붙여(한 장에 최대 3컷, 같은 쇼트 안의 컷부터, 첫·마지막 컷은 되도록 따로) 모든 컷이 들어가게 첨부합니다. 프롬프트는 ‘reference image 3 (left frame)’처럼 어느 칸인지 지시하고, 나란히 붙인 그림을 분할 화면으로 그리지 말라고 덧붙입니다. 18컷을 넘을 때만 덜 중요한 컷을 빼고 렌더 전 점검이 알려 줍니다. 직접 만들기용 ZIP과 ‘합쳐서 받기’도 같은 그림을 줍니다.

### Facial Acting Studio에서 달라진 점
- 데이터: `mode`(`cast` 인물별 / `storyboard` 컷 단위), 스토리보드용 `extras`(군중)와 표정별 `action`·`camera`·`sketchAssetId`.
- 데이터: `character` 하나 → `title`(장면 이름) + `style`(공통 그림체) + `baseAssetId`(장면 기준 그림 한 장) + `cast[]`(인물 1~4명, 위치·목소리 포함). 표정에 `characterId`(중심 인물)와 `reactions[]`(나머지 인물 각각의 연기) 추가. `dialogue.voice` → 인물별 `voice`.
- Facial Acting Studio의 프로젝트 데이터(JSON)를 그대로 넣어도 1명짜리 장면으로 열립니다(`parseProjectData`가 자동 변환).
- DB: `save_project`가 `title`과 장면 기준 그림으로 작업 이름·썸네일을 갱신합니다. **Facial Acting Studio와 다른 Supabase 프로젝트를 쓰세요**(같은 표 이름을 씁니다).
- 표정 수 최대 8 → 12 (여러 인물이 주고받는 장면용, Higgsfield 한 번 생성 한도).

## 기존 앱의 문제와 개선점

| 기존 문제 | 새 앱 |
|---|---|
| 복구할 때마다 `· 복구 · 복구` 사본 작업이 생김 | 작업 하나에 버전 기록이 쌓임. 되돌리기도 새 버전으로 기록. 사본을 만들지 않음 |
| 저장 충돌, 미저장 초안, 임시 작업 안내가 동시에 뜸 | 작업마다 브라우저 초안 1칸. 충돌 시 "최신본 불러오기 / 내 변경으로 저장" 중 선택하며, 어느 쪽도 기록에서 사라지지 않음 |
| AI가 모든 칸의 얼굴 방향을 같은 값으로 기록 | 방향은 항상 화면 기준 5단계로 기록. AI가 추정한 방향은 사람이 확인해야 승인 가능. 얼굴·몸 방향이 반대면 경고. 위에서 본 스케치로 표시 |
| 다른 그림체의 표정집이 섞일 위험 | 기본값은 "표정만 참고". AI가 그림체 차이를 경고하고, 프롬프트에 "그림체 복사 금지"를 명시 |
| 같은 AI 버튼이 여러 곳에 있음 | AI 기능 버튼은 단계 화면에만 있고, 오른쪽 패널은 대화만 함 |
| 상태 안내 패널이 작업 영역을 밀어냄 | 상단 배지 하나에 저장 상태와 AI 작업 수를 표시. 작업 목록과 팀 관리는 별도 페이지 |
| 7~10px 연한 글씨 | 본문 15px, 최소 13px, 모든 글자색 대비 4.5:1 이상 |
| 로그인 전에도 JS와 예시 그림 공개 | 모든 경로를 로그인으로 보호. 프롬프트 템플릿은 서버에만 둠. 파일은 비공개 저장소의 서명 URL로만 열람 |
| 팀원 등록 후 사이트 공유 설정을 따로 해야 함 | 관리자가 이메일을 등록하면 그 이메일로 로그인하는 즉시 사용 가능 |

기존 앱에서 유지한 장점:
- 단계별 승인과 승인 후 수정 시 재검토 규칙
- AI가 지어내지 않고 확인 질문을 남기는 방식
- 사람이 적용해야만 반영되는 AI 제안
- 창을 닫아도 계속되는 AI 작업
- 역할 권한(관리자·편집자·검토자), 하루 AI 한도, 검토 의견

## 설정 방법 (처음 한 번)

### 1. Supabase
1. [supabase.com](https://supabase.com)에서 새 프로젝트를 만듭니다.
2. **SQL Editor**에서 `supabase/migrations/0001_init.sql` 전체를 실행합니다.
3. 첫 관리자를 등록합니다. 같은 SQL Editor에서 이메일만 바꿔 실행하세요.
   ```sql
   insert into workspaces(name) values ('5Bricks 공용 작업함');
   insert into workspace_members(workspace_id, email, role)
     select id, 'you@example.com', 'admin' from workspaces where name = '5Bricks 공용 작업함';
   ```
4. **Authentication → Providers**에서 Google을 켭니다(이메일 로그인 링크는 기본으로 켜져 있음).
5. **Authentication → URL Configuration**에서 다음을 설정합니다.
   - Site URL: 배포 주소 (예: `https://your-app.vercel.app`)
   - Redirect URLs: `https://your-app.vercel.app/auth/callback`, `http://localhost:3000/auth/callback`

### 1-1. Higgsfield 연결 (관리자, 한 번)
1. `supabase/migrations/0002_higgsfield.sql`도 SQL Editor에서 실행합니다.
2. 앱의 **팀·사용량 → Higgsfield 연결 → Higgsfield 로그인 열기**를 누릅니다.
3. Higgsfield에 로그인하고 허용을 누르면 "사이트에 연결할 수 없음" 화면이 뜹니다. 정상입니다.
4. 그 화면의 **주소창 전체**를 앱에 붙여넣고 **연결 완료**를 누릅니다.
5. 크레딧을 쓸 워크스페이스를 고릅니다(기본: 개인 워크스페이스).

Higgsfield는 웹사이트 주소로 돌아오는 로그인을 허용하지 않아서 이렇게 "주소 붙여넣기" 방식을 씁니다. 토큰은 서버 전용 표(RLS, 정책 없음)에만 저장됩니다. Higgsfield의 워크스페이스 선택은 계정 전체에 적용되지만, 앱은 요청할 때만 잠깐 바꿨다가 원래 선택으로 되돌립니다.

### 2. Claude API 키
[console.anthropic.com](https://console.anthropic.com)에서 API 키를 만듭니다.

Claude 요청은 프롬프트 캐시(5분)를 씁니다. 그림을 요청 맨 앞에 두고 그림까지를 캐시하므로, 같은 작업을 다시 돌리거나 ‘AI와 상의’에서 이어 물을 때 그림을 다시 읽지 않습니다(캐시에서 읽은 부분은 기본 모델 기준 입력 단가의 약 5%, 응답 시작도 빨라짐). 적중 여부는 Console의 Usage에서 cache read 토큰으로 확인할 수 있고, ‘팀·사용량’의 입력 토큰은 캐시에서 읽은 양까지 합한 전체 입력입니다.

### 3. Vercel
1. 이 저장소를 GitHub에 올리고 Vercel에서 Import합니다.
2. Environment Variables에 `.env.example`의 값을 넣습니다.
3. Deploy를 누릅니다.

> AI 작업은 응답을 보낸 뒤 서버에서 계속 실행됩니다(`after()`, 최대 300초). Vercel 플랜에 따라 함수 최대 실행 시간이 다를 수 있습니다.

### 로컬 실행
```bash
cp .env.example .env.local   # 값 채우기
npm install
npm run dev
```

## 사용 흐름
1. **출연진:** 인물마다 기본 그림을 올리고 "AI로 기본 그림 분석"을 누릅니다. 제안 중 원하는 항목만 골라 적용하고, 확인 질문에 답한 뒤 승인합니다. 여러 인물이면 화면 위치도 정합니다.
2. **표정:**
   1. 참고 시트(선택)를 올리고 "AI로 표정 설계"를 누릅니다.
   2. 각 카드에서 방향을 확인합니다.
   3. "프롬프트와 참고 그림 묶음 만들기"를 누르고, higgsfield.ai에서 구독 크레딧으로 생성합니다.
   4. 결과 시트를 올리고 "AI로 시트 검사"를 실행한 뒤 승인합니다.
3. **대사:** AI 제안 후 다듬습니다. 대사 길이가 구간보다 길면 경고가 뜹니다.
4. **액팅:** 타임라인을 정합니다. 구간이 빈틈없이 이어져야 하고 전체 60초 이하여야 승인할 수 있습니다.
5. **영상 프롬프트:** 프롬프트를 복사해 Higgsfield에서 영상을 만들고, 결과 MP4를 올려 최종 승인합니다.

승인은 팀 검토용입니다. 각 단계 아래 ‘승인 없이 다음 단계로’로 바로 넘어갈 수 있습니다.

표정 그림(2단계): ① 기준 그림을 고르면 나머지 표정 비용 확인이 바로 열리고, 새 결과가 여러 장이면 ‘새 결과 모두 사용’으로 한 번에 씁니다.
그림이 모두 지금 규칙으로 준비되면 ‘AI로 표정 그림 검사’가 자동으로 한 번 돕니다.

## 상황 설정·기초 대사
2단계 ①의 **상황 설정·기초 대사**에 장면 상황과 기초 대사를 적으면:
- **AI로 표정 설계**가 이 장면을 연기하는 표정을 순서대로 설계합니다. 대사마다 표정을 배정하고, 남는 표정은 대사 전·사이·후의 반응으로 씁니다. 표정 참고 시트가 있으면 장면에 맞는 칸을 골라 분석합니다.
- 3단계 **AI로 대사 작성**은 기초 대사를 고치지 않고 그대로 배치합니다(대사 언어가 다르면 그 언어로 옮김). 4단계 분배 설계도 장면의 흐름을 따릅니다.
- 카메라 움직임·배경은 표정 그림(흰 배경)에 그리지 않으므로, 영상에 넣으려면 5단계 추가 연출에 적습니다.

## 영상 프롬프트 규칙
- 맨 앞: **컷 없는 한 쇼트**라는 지시. 표정 그림들도 한 쇼트의 순간들로 그립니다.
- 그다음: 구간별 연기, 이어서 **추가 연출(감독 지시)** — 줄이지 않고 줄바꿈까지 그대로, 제약사항 바로 앞에 `DIRECTOR'S DIRECTION`으로 들어감.
  카메라 장비·움직임·각도·배경은 앱의 기본 문장보다 우선(예: Steadicam이면 제약사항의 HANDHELD 문장이 그 장비로 바뀜).
  카메라 지시도 여기에 씀. 시간(예: 0–3s)은 영상 길이에 맞춰 씀.
  (예전의 별도 ‘카메라 연출’ 칸에 쓴 글은 프로젝트를 열 때 추가 연출 맨 앞으로 옮겨짐)
- 맨 끝: **스튜디오 제약사항** (`src/lib/domain/constraints.ts`의 `STUDIO_CONSTRAINTS`).
- **프롬프트에 적용:** 추가 연출 아래 버튼이 바로 저장하고 프롬프트를 다시 만들어 ‘프롬프트에 들어 있습니다’와 들어간 모습·최종 프롬프트를 보여 줌.
  버튼을 누르지 않아도 입력을 멈추면 자동 저장되고 프롬프트가 따라 바뀜.
- **영어 정리 (AI):** 팀의 한국어 설계(특징·의상·그림체·목소리·표정별 연기·전환·말투)를 영상·그림 모델용 짧은 영어로 옮김.
  2단계·5단계의 ‘AI로 영어 정리’ 또는 렌더 전 점검의 버튼으로 만들고, 도착하면 바로 적용됨.
  5단계에서는 영어 정리가 없거나 설계가 바뀌어 어긋나면(예: AI 점검 수정 적용 뒤) 저장된 버전마다 한 번 자동으로 다시 만들고,
  그동안 ‘비용 확인 후 생성’은 기다림(영어가 반영된 프롬프트로 렌더되도록).
  - 영상 프롬프트: 구간마다 영어 한두 문장 + 대사 원문 + 영어 말투, 언어 이름도 영어(예: 고대 아랍어 → Classical Arabic). 추가 연출은 원문 그대로.
  - 표정 그림 프롬프트: 긴 한국어 특징·외형 대신 영어 특징 목록(이 프로젝트 기준 약 5,000자 → 3,000자).
  - 조각마다 만든 때의 한국어를 기억해서, 설계를 고치면 그 부분만 한국어로 돌아감(렌더 전 점검이 다시 정리하라고 알려 줌).
  - 영어가 없을 때 한국어는 문장·구절 단위로 줄이고(괄호 안에서 자르지 않음), 한 구절도 안 들어가면 그 칸은 뺌. 길이가 넘치면
    얼굴·팔손 설명부터 빼고 ‘다음 표정으로’(전환)는 끝까지 남김. 마지막 구간에는 전환을 넣지 않음.
- **모핑·연결:** 앱의 일반 문장에 “얼굴형·눈 모양·비율은 모든 구간에서 같고 표정 근육과 자세만 바뀜”,
  “표정 변화는 깜빡임·숨·고개 돌림·손 동작에 실려 중간 포즈를 거침, 얼굴이 녹듯 바뀌지 않음”, “인물의 위치·크기 유지”를 넣음.
  영어 정리의 전환 문장도 이런 몸 동작으로 씀. 스튜디오 제약사항은 원문 그대로.
- **자동 조율:** 팀이 쓴 문구(팔·손 동작, 다음 표정으로, 대사 말투, 목소리, 추가 연출)가 제약사항과 부딪히면 영상 프롬프트에서만 고칩니다.
  - ‘컷’ 표현 → 구간·표정 전환, 음악 지시 삭제, 모핑·보간·모션 블러·미끄러지는 움직임 삭제, 움직임의 ‘부드럽게’ 삭제
  - 추가 연출의 카메라 문장(카메라가 주어인 문장, `CAMERA` 제목 아래 문장)은 고치지 않음.
    카메라 지시가 없으면 정지 화면, 구간 설명에만 움직임이 있으면 핸드헬드
  - 고친 내용은 5단계 ‘렌더 전 점검’에 전/후로 표시, 원래 문구는 앱에 그대로 남음
- **렌더 전 점검**(5단계 생성 버튼 바로 위): ‘충돌 점검’이 저장 후 프롬프트를 다시 만들고 확인할 점·자동 조율·문제 없음을 보여 줌.
  확인할 점마다 고치는 버튼이 있음:
  - 추가 연출의 카메라 시간이 영상 길이와 다르면 ‘N초에 맞추기’(예: 8초 기준 0–3s·3–6s·6–8s → 10초 기준 0–4s·4–7.5s·7.5–10s)
  - 상황 설정의 카메라 움직임 → ‘추가 연출로 옮기기’, 표정 그림·대사 시간 등 → 고칠 단계로 이동
  - 프롬프트가 길면 ‘AI로 줄일 안 만들기’
- **AI로 정밀 점검:** 최종 프롬프트 전체를 읽고 남은 모순을 찾아 **고칠 글까지** 제안. 각 안은 바뀌는 부분만 표시되고 ‘이대로 고치기’(또는 ‘모두 적용’)를 눌러야 바뀜.
  - 추가 연출은 그 칸의 글이 바뀜(영상 단계 승인만 다시 필요).
  - 승인된 단계의 글(다음 표정으로, 팔·손 동작, 표정 메모, 대사 말투, 목소리)은 그대로 두고 **영상 프롬프트에만** 고친 글을 씀.
    그 단계의 원래 글이 바뀌면 자동으로 쓰지 않으며, 점검 화면에서 ‘되돌리기’로 지울 수 있음.
  - 점검 뒤에 바뀐 칸의 안은 적용되지 않음(다시 점검).
- **시작·끝 프레임 (5단계 고급):** 시작 프레임에 끝 프레임까지 넣으면 영상이 그 장면에서 끝남(Kling 4.0·MiniMax H3, Seedance는 시작 프레임만).
  ‘프레임 그림 만들기’로 표정 그림의 순간을 영상 비율·원하는 구도(클로즈업/바스트/미디엄)로 다시 그려 시작·끝 프레임으로 씀.
  카메라 움직임(클로즈업 → 바스트 등)은 글보다 두 프레임으로 정하는 편이 정확함.
- **생성한 영상:** Higgsfield 영상이 끝나면 바로 ‘생성한 영상’에 들어감(검토 링크에서도 보임). 드래프트는 1080p 확정 카드가 남음.
- **모델 안내:** 영상 — Kling 4.0 최종본 추천, Seedance 2.5 빠른 확인용(카메라 지시 약함), Gemini Omni Flash 1.2(소리 포함, 시작 프레임만이면 최대 15초·참고 그림/끝 프레임이면 최대 10초, 720p·1080p·4K), MiniMax H3는 흰 배경을 무시하는 경우가 있음. 그림 — Nano Banana 2.1, GPT Image 2.6 Sunburst·Flare(1K, 첫 장면 기본), Seedream 5.0 Pro(2K).
- **Higgsfield 직접 제작용 ZIP:** 2단계(표정마다 폴더: 참고 그림 + 프롬프트), 5단계(첨부 순서대로 참고 그림 + 프롬프트 + 작업 안내)

## 검토용 링크
작업 화면 위쪽 **검토용 링크**(관리자·편집자)로 로그인 없이 그 작업을 **보기만** 할 수 있는 링크를 만듭니다.
- 보이는 것: 단계별 설계 내용, 표정 그림·영상, Higgsfield에 보내는 프롬프트, 생성·AI 작업 기록, 검토 의견, 버전 기록. 팀원 이메일은 보이지 않습니다.
- 기간: 1시간 / 24시간 / 7일 중 선택. 기간이 끝나면 자동으로 막히고, "이 작업의 링크 모두 끊기"로 미리 막을 수도 있습니다.
- 도구용 JSON: `/api/review/<링크 토큰>`
- 링크는 서버 키(`SUPABASE_SERVICE_ROLE_KEY`, 또는 따로 둔 `REVIEW_LINK_SECRET`)에서 만든 서명으로 검증하므로 DB 표가 필요 없습니다. 서버 키를 바꾸면 기존 링크는 모두 무효가 됩니다.

## 운영 메모
- **AI 작업 시간:** Claude 작업은 응답 뒤 서버에서 최대 800초(Vercel Pro) 돕니다. 15분이 지나도 끝나지 않은 작업은 ‘시간 초과’로 닫혀 버튼이 다시 살아납니다.
- **자동 AI 호출:** 5단계 영어 정리와 2단계 그림 검사는 자동으로 한 번 요청되고 하루 AI 한도에 포함됩니다. 영어 정리는 바뀐 부분이 달라질 때만 다시 요청하며(같은 결과로 반복하지 않음), 자동 요청이 거절되면 그 자리에 이유를 보여 줍니다.
- **Higgsfield 워크스페이스:** 워크스페이스 선택은 계정 전체에 적용되므로, 선택을 바꾸는 Higgsfield 호출은 작업함마다 한 번에 하나씩 돕니다(`higgsfield_connections.lock_until`, 최대 90초). 결과 저장은 먼저 잡은 쪽만 합니다(`ai_jobs.claimed_at`).
- **리전:** Vercel `dub1`(더블린)과 Supabase `eu-west-1`(아일랜드)이 같은 지역이라 맞춰져 있습니다. Supabase를 다른 지역에 만들면 `vercel.json`의 regions도 그 근처로 바꾸세요.
- **작업함:** 한 사용자는 한 작업함(가장 먼저 등록된 곳)만 봅니다. 의도된 동작입니다.
- **영상 파일 크기:** Supabase 무료 플랜은 파일당 50MB까지라 1080p·30초 영상은 저장에 실패할 수 있습니다(오류 메시지가 뜸). 필요하면 플랜의 파일 한도를 올리세요.
- **저장 데이터를 읽지 못하면:** 빈 장면으로 열되 자동 저장과 AI 요청을 멈추고 경고를 띄웁니다. ‘기록’에서 이전 버전으로 되돌리면 풀립니다.
- **Google 로그인:** Supabase에서 Google을 켠 뒤 환경 변수 `NEXT_PUBLIC_ENABLE_GOOGLE_LOGIN=1`을 넣으면 버튼이 나타납니다.
- **새 DB:** `supabase/migrations`의 SQL을 번호 순서대로 모두 실행하세요(`npm run test:sql`도 전부 실행해 검사).

## 개발
```bash
npm test          # 도메인 로직 단위 테스트
npm run typecheck
npm run lint
npm run build
```

구조:
- `src/lib/domain/`: 데이터 모델, 승인 규칙, 방향 검사, Higgsfield·영상 프롬프트 생성(서버 전용)
- `src/lib/ai/`: Claude 작업 스키마, 프롬프트, 실행기
- `src/app/projects/[id]/`: 에디터(단계 화면, 상의, 버전 기록, 검토 의견)
- `supabase/migrations/`: DB 스키마, RLS, 버전 저장 함수
